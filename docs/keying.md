# HF waveform keyings

A *keying* is the set of pseudo-random tables an HF waveform is built on. Two
stations can only hear each other if they use the same keying. This document
describes the keyings xara supports, the files they are stored in, and exactly
how `xara-keygen` derives a keying from a name, so that anyone can reproduce a
published one.

Status: EXPERIMENTAL. The 2027 keying has been tested xara-to-xara only. It
has not been tested on air against VARA HF 4.9.1.

## The three kinds

| keying | used when | where the tables come from |
|---|---|---|
| legacy | default; VARA HF up to 4.9.0, and 4.9.1 before 2027 | generated by xara |
| 2027 | VARA HF 4.9.1 once its clock reaches 2027 | files from your own VARA HF 4.9.1 install |
| named | whenever `--vara-dir` points at one | files written by `xara-keygen` |

xara does not ship or redistribute VARA's table files. The 2027 keying only
works if you install VARA HF 4.9.1 yourself and pass its directory with
`--vara-dir`.

The keying is chosen once at startup and is fixed for the life of the
process. `--waveform auto|legacy|2027` controls the choice; see the README.

## What a keying contains

For every speed level of every bandwidth:

- **channel interleaver**: a permutation of the `N` coded bits of a frame. It
  spreads neighbouring bits over carriers and time.
- **turbo interleaver**: a permutation of the `K` information bits, used
  between the two constituent encoders of the turbo code.
- **marker section** (`other`): the positions of the known reference symbols
  in each carrier; for the FSK levels, the tone sequence and pilot values.

And for the whole waveform:

- **OFDM phase table**: 128 rows of 469 phase indices.
- **PSK phase table**: 13 rows of 471 phase indices.
- **control seed offset**: a number added to the seed of every control-code
  codebook (connect, acknowledge, break, and so on).

A phase index `v` is in `0..=128` and means a rotation of `2*pi*v/128`.

The bit-whitening sequence is the same in every keying.

## Files

A keying directory holds:

| file | content |
|---|---|
| `Binary1.dat` | tables for 500 Hz |
| `Binary2.dat` | tables for 2300 Hz |
| `Binary3.dat` | tables for 2750 Hz |
| `Mod1.dat` | OFDM phase table |
| `Mod2.dat` | PSK phase table |
| `xara-keying.txt` | named keyings only: name, generator version, seed offset |

A directory without `xara-keying.txt` is treated as a VARA HF 4.9.1 install
and gets the control seed offset 687.

### `BinaryN.dat`

One record per level, in level order. Each record is:

1. the turbo interleaver, `K` entries
2. the channel interleaver, `N` entries
3. the marker section, `other_len` entries of 16 bits

All integers are big-endian. Interleaver entries are 16 bits, or 24 bits when
the permutation is longer than 65536. The file ends with a CRC-16/GENIBUS,
big-endian, computed over the body *minus its last byte*.

(The legacy table files of VARA HF up to 4.9.0 have the same layout with the
channel interleaver first.)

xara rejects a file if the checksum is wrong, if any interleaver is not a
permutation of `0..len`, or if the length does not match the level table.

### `Mod1.dat` and `Mod2.dat`

One byte per phase index, no header and no checksum. Each file is stored in
two blocks: the first block holds the leading symbols of every row, the second
the remaining symbols of every row.

| file | rows | symbols per row | first block | size |
|---|---|---|---|---|
| `Mod1.dat` | 128 | 469 | symbols 0..409 | 60032 bytes |
| `Mod2.dat` | 13 | 471 | symbols 0..411 | 6123 bytes |

### `xara-keying.txt`

Plain text, `key = value` lines, `#` comments. `seed-offset` is required; it
is the control seed offset. `name` and `generator` are informational.

## Named keyings: generator version 1

`xara-keygen --name NAME --out DIR` writes the keying called `NAME`. The name
is the whole definition: the same name gives byte-identical files on every
machine. A name is 1-64 characters of `A-Z a-z 0-9 - _ .` and is case
sensitive.

Everything is drawn from SplitMix64 streams. The stream for a *part* is seeded
with the 64-bit FNV-1a hash of the ASCII string

    xara-keying/1/<part>/<NAME>

`draw(m)` takes the next 64-bit output `x` and returns `floor(x * m / 2^64)`.

| part | what is drawn |
|---|---|
| `tables-500`, `tables-2300`, `tables-2750` | for each level in order: the channel interleaver, the turbo interleaver, then the marker section |
| `psk` | the PSK phase table, row by row, each index `draw(129)` |
| `ofdm` | the OFDM phase table, row by row, each index `draw(129)` |
| `seed-offset` | the control seed offset, `1024 + draw(31000)` |

A permutation of length `n` is built by calling `draw(n)` repeatedly and
keeping each value the first time it appears, until all `n` are present.

The marker section follows the same placement rules as the legacy keying, with
this generator in place of the legacy one; see `fsk_other` and `psk_other` in
`crates/xara-phy/src/dat.rs`, which are the reference.

Note the order inside a stream (channel interleaver first) differs from the
order in the file (turbo interleaver first).

The generator is pinned by a test (`generator_v1_is_stable`). Any change to
the algorithm must increase the generator version, so a published name never
changes meaning.

## What a named keying is and is not

- Stations on different keyings ignore each other completely: data frames and
  control codes, including connect requests.
- It is **not encryption** and gives no privacy. Anyone who knows the name
  can decode everything.
- It cannot talk to VARA or to any station on another keying.
- On amateur bands the name you use must be published, so the emission stays
  a documented one. Check the rules that apply to you.

## Testing

    cargo test -p xara-phy
    XARA_KEYING_NAME=NET-7 cargo test -p xara-phy --test keying_2027
    XARA_VARA_DIR=/path/to/VARA cargo test -p xara-phy --test keying_2027

The second and third run an audio loopback at every level under a named
keying and under your own VARA HF 4.9.1 files. Without those variables the
keying tests are skipped; no VARA file is needed to build or test xara.
